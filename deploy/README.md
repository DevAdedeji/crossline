# Hosting preparation — not activated

The Nuxt web client can target Vercel, with repository root directory `apps/web` and the workspace install/build commands in `vercel.example.json`. Nuxt selects the Vercel Nitro target in that environment. The checked-in file is an example, not an activated project. No account limits have been changed.

Colyseus is a separate long-running process. The Railway example builds that process, but its production refusal remains deliberate. The continuous arena uses one process and one room, with eight tested seats. Do not add replicas: the singleton guard and temporary reconnect reservations are process-local. A process restart creates a fresh arena; durable account totals survive only when the database integration is configured.

Approved deployment configuration will need `NUXT_PUBLIC_MATCH_URL=wss://<public-match-host>` on the web service, and `WEB_ORIGIN=https://<web-host>`, `MATCH_HOST=0.0.0.0`, and the platform `PORT` on the match service. Localhost addresses are for local development only. Review secure origins, public admission/rate/resource limits, transport reconnects, observability and the production guard before any public launch.

Online authentication and statistics use Better Auth / Drizzle with PostgreSQL. The match service needs approved `DATABASE_URL`, a strong `BETTER_AUTH_SECRET`, HTTPS `WEB_ORIGIN`, and explicit verification sender configuration: `AUTH_EMAIL_ENABLED=1`, `AUTH_EMAIL_FROM`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`. SMTP uses verified TLS on port 465 or required STARTTLS on 587. These settings are inactive; no real mail has been sent. The PostgreSQL pool remains bounded to 1–5 connections (default 3), with verified remote TLS and query/connect timeouts. Migration tooling reads `packages/db/.env` only when deliberately invoked. Review and explicitly apply all three migrations to the intended database; startup never applies hosted migrations.

The Nuxt `/api/auth/**` route proxies only to the configured match host and preserves verification redirects and HttpOnly session cookies. Better Auth owns hashing, verified-email sessions and short-lived one-time admission tokens. Colyseus validates the account/session before join and reconnect control; logout/expiry revoke access. Emails and credential/session fields never enter the shared room state or leaderboards. Historical guest tables remain separate and cannot claim account totals.

`AUTH_DEV_LOCAL=1` is restricted to nonproduction loopback, uses a known local fixture secret, accepts only `@example.test` addresses and captures verification messages locally. Never deploy or expose this mode. Local persistent files live under ignored `.crossline-local/`; tests use disposable databases. This local mode does not demonstrate real email delivery or hosted PostgreSQL connectivity.

Before removing the production startup guard, review trusted proxy/IP handling (the current auth gateway uses a conservative single global rate bucket), verified cookie forwarding, all origin settings, resource/admission limits, disconnect behavior and observability. The single arena remains capped at eight verified seats. The in-process statistics retry queue can lose uncommitted events during a crash; do not claim crash-proof delivery.

Aiven project/database provisioning, service credentials, migration execution on a hosted database and deployment are not performed by these files. Credential creation requires action-time approval and secure user entry into the selected service. Do not copy passwords/connection strings into chat, source, screenshots or logs. The existing Railway spend limit remains unchanged.
