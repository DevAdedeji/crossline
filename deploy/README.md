# Hosting preparation — not activated

The Nuxt web client can target Vercel, with repository root directory `apps/web` and the workspace install/build commands in `vercel.example.json`. Nuxt selects the Vercel Nitro target in that environment. The checked-in file is an example, not an activated project. No account limits have been changed.

Colyseus is a separate long-running process. The Railway example builds that process, but its production refusal remains deliberate. The continuous arena uses one process and one room, with eight tested seats. Do not add replicas: the singleton guard and temporary reconnect reservations are process-local. A process restart creates a fresh arena; durable guest totals survive only when the database integration is configured.

Approved deployment configuration will need `NUXT_PUBLIC_MATCH_URL=wss://<public-match-host>` on the web service, and `WEB_ORIGIN=https://<web-host>`, `MATCH_HOST=0.0.0.0`, and the platform `PORT` on the match service. Localhost addresses are for local development only. Review secure origins, public admission/rate/resource limits, transport reconnects, observability and the production guard before any public launch.

Optional PostgreSQL persistence uses `DATABASE_URL` on the match service, a pool of three connections (configurable 1–5), five-second connect/query limits, and verified TLS for remote databases. `DATABASE_CA_FILE` can point to an approved provider CA file; TLS verification is never disabled for a remote host. No database URL belongs in browser/public configuration. Migration tooling reads `packages/db/.env` only when deliberately invoked. Review and apply both SQL migrations to the intended database before enabling persistence. Do not reuse another project's database or credentials.

Guest capabilities are issued by the server during ordinary play and stored in the player's browser; the database stores only their SHA-256 hashes. Display names are not authentication. Clearing browser storage loses that guest identity; there is no account recovery in this prototype. Server-confirmed elimination IDs deduplicate transactional kill/death updates. A bounded in-process retry queue covers temporary write failures, with a visible saving-delayed state; uncommitted events can be lost on a process crash. An external durable event queue and recovery policy are still required before claiming crash-proof statistics.

Aiven project/database provisioning, service credentials, migration execution on a hosted database and deployment are not performed by these files. Credential creation requires action-time approval and secure user entry into the selected service. Do not copy passwords/connection strings into chat, source, screenshots or logs. The existing Railway spend limit remains unchanged.
